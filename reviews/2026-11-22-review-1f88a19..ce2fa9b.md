# langwb review — 2026-11-22, commits `1f88a19..ce2fa9b`

This review covers the seven local commits on `main` that are ahead of
`origin/main` (`1f88a19`), on macOS (Darwin):

| commit | subject |
|---|---|
| `ca5b727` | Hardening 4.5 (1/3): closure capture via IF1 partial application + LLVM closure emission |
| `f860eca` | Hardening 4.5 (2/3): extract `contour_clone.cc`, unify staged pipeline, bounded re-analysis |
| `8bdf821` | Hardening 4.5 (3/3): source-mapped IFA diagnostics |
| `17e967d` | Step 5: `using syntax` regions, GLR `Amb` 3-tier disambiguation, grammar hygiene |
| `7676c9f` | Step 6: lists, `match`, quasiquote, record reflection, `eval_value` |
| `c39f8f2` | Step 7: `check` declarations, contour cloning for `def` blocks and record methods |
| `ce2fa9b` | Operator precedence (`$left`) and eager parsing of declaration bodies |

The diff touches 24 files (+3,035 / −679). It includes two edits to the
`ifa/` subtree (`ifa/codegen/cg_emit_llvm.cc`). The build has no warnings.
`make test` passes: the smoke tests, all `examples/minilang/*.ml`, and 93
cases in `tests/run_tests.sh`, in about 5 s.

Each finding below was reproduced with `./langwb -e '…'` using the expression
quoted with it. Where a finding says "regression", the same input was run on
an `origin/main` build in a scratch worktree for comparison.

The top three:

1. **Closure capture is incomplete and can segfault (§2.1).** A capturing
   closure called from any scope other than the one that defined it crashes
   IFA. Examples are a closure called from another closure, or one stored in
   a record. Mutually recursive `def`s that capture also fail. The README
   now advertises closures without listing these limits.
2. **Top-level values print wrong results (§2.2).** `5 == 5` prints `0`,
   which is a regression from `1` on `origin/main`. `[1, 2, 3]` prints a heap
   address. Any value that is not an `int64`, a string, a record or a
   function is silently classified as `Int64`, giving `strtoll("<val>") == 0`.
3. **Tier-3 ambiguity resolution is exponential and has a hard cap (§2.4).**
   A program with 10 independent ambiguous sites is rejected with the false
   message "0 of 2 alternatives valid". Nine sites take about 3 s.

---

## 1. What the range delivered

There is a lot of real progress here. The most valuable pieces:

- **Precedence is fixed.** On `origin/main`, `10 - 3 - 2` gives `9` and
  `3 * 3 + 4 * 4` gives `57`. Both are now correct (`5`, `25`). Switching to
  `$left N` with `set_op_priority_from_rule = 1` (`src/parse/parse.cc:240`)
  is the right DParser setting. The old `$binary_op_left` modifiers were never
  resolving the ambiguity.
- **Eager parsing of declaration bodies (`ce2fa9b`) is done the right way.**
  `decl_grammar_` keeps only the heads (`macro_kw ident '=>'`, and so on).
  The body is parsed with `compiled_grammar()->parse_prefix(…, "expr")`, then
  `;` is expected (`workbench.cc:417`). There is no recompilation of
  `decl_grammar_`, and `body_text` with its `[^;(){}"]+` regex is gone.
  Syntax errors in a macro that is never called are now reported, which the
  new test `eager_decl_parse_uncalled_macro_syntax_error` covers. Expansion
  and JIT compilation stay lazy, so macros can still call macros declared
  later. `for_syntax` bindings are now spliced as syntax
  (`wrap_for_syntax_stx`), not by string concatenation.
- **Clone names are hygienic.** Contour clones now get a fresh `ScopeSet`
  (`contour_clone.cc:123`), so the capture problem from the previous review's
  §2.2 is fixed. `let sum_fields = 7 in sum_fields` gives `7`.
- **Simple closures work:** `let a = 5 in let f = fn(x) => x + a in f(1)`
  gives `6`. Curried closures (`add(2)(40)`), returned closures, and captured
  strings, records and bools all work too.
- **IFA errors carry source positions:** `<input>:1:22` and
  `<macro:getb@1:20>:1:11` instead of `<unknown>:0`.
- **Quasiquote and `match` are hygienic.** `let __m__ = 5 in match 1 { x =>
  __m__ + x }` gives `6`. A template's `let r = …` does not capture the
  user's `r`.
- **Scoped syntax regions work for the main use case.** The two conflicting
  `op` extensions in `examples/minilang/scoped_glr.ml` coexist.

## 2. Findings

### 2.1 Closure capture (`ca5b727`)

`lower_lambda` (`src/ifa_bridge/bridge.cc:573`) finds free variables, adds
them as leading hidden parameters, and emits a `Partial_OK` send at the
definition site. That design is sound. Three gaps remain:

**(a) Calling a closure from another closure, or from a record, segfaults.**

```
$ ./langwb -e 'let a = 1 in let f = fn(x) => x + a in let g = fn(y) => f(y) in g(3)'
Segmentation fault: 11
$ ./langwb -e 'let k = 1 in let ops = { t: fn(p) => p + k } in ops.t(1)'
Segmentation fault: 11
```

Both crash at `to_concrete_type(t=nullptr)` in `ifa/…/clone.cc:115`. The same
closure works when passed as an argument (`h(f, 3)` gives `4`), so the problem
is specific to a closure *captured* as a free variable or stored in a record
field. On `origin/main` the first case failed with a clean IFA error; it now
crashes the process. Step 7's "record-stored method" cloning depends on this
path, so `let k = 1 in let ops = { t: fn(p) => sum_fields(p) + k } in …` also
segfaults.

**(b) Mutually recursive `def`s that capture are lowered with the wrong arity.**

```
$ ./langwb -e 'let k = 5 in { def a = fn(x) => if x == 0 then k else b(x - 1);
                                def b = fn(x) => a(x) + k; a(3) }'
error: illegal call argument type '__wb_deffn_b_2'
```

While `a` is lowered, `b` is still bound to its pre-allocated `fn` symbol,
which has `is_fun = 1`. `collect_free_captures` skips `is_fun` symbols
(`bridge.cc:560`), so `a` calls `b` directly without `b`'s hidden capture
parameters. `rec_self_caps` handles direct self-calls only. It needs to cover
every function in the `def` group, with each group's captures computed before
any body is lowered.

**(c) A self-call from inside a nested lambda fails.**

```
$ ./langwb -e 'let k = 7 in rec f = fn(n) => if n == 0 then k else (fn(y) => f(y))(n - 1) in f(2)'
error: 'k' has no type
```

`rec_self_caps[fn]` (`bridge.cc:642`) is still active while the inner lambda
is lowered. The inner call to `f` therefore passes the *outer* function's
capture parameter symbols, which are locals of a different function. They
need to be captured by the inner lambda in turn.

The three tests added for closures cover only the cases that work. Add (a),
(b) and (c) as tests. Until they pass, also list them in the README's
*Status & Limitations* section.

**`ifa/` edits.** The closure construction in `cg_emit_llvm.cc`
(`emit_send_call_impl`, around line 3447) and the dead-field elision change in
`emit_send_setter` belong to the upstream IFA subtree. They need a
`make push-ifa` or an upstream PR, or the next subtree pull will conflict.
Two smaller points about the construction code:

- When `closure_struct` is unsized, it falls through to ordinary call
  emission for a `Partial_OK` send. Failing loudly would be safer.
- It widens mismatched integers with `CreateSExtOrTrunc`, so a captured `i1`
  `true` would be stored as `-1`. Use `ZExt` for `i1`.

### 2.2 `eval_value` misreports non-integer results (`7676c9f`), a regression

```
$ ./langwb -e '5 == 5'          # origin/main: 1
0
$ ./langwb -e '[1, 2, 3]'
4395682176
$ ./langwb -e '{ x: 5 == 5 }'
{ x: <val> }
```

The `wb_emit_val` emitter (`bridge.cc:1277`) writes `<val>` for any LLVM type
other than `i64`, string or function. `compile_and_jit_value` then defaults
the kind to `Int64` and runs `strtoll("<val>")`, which gives `0`
(`bridge.cc:1709`). Lists are pointers that reach the `i64` path, so their
address is printed. The README claims `eval_value` supports int64, string,
record and function values. Fix this in three steps:

- Emit `true`/`false` for `i1`.
- Emit lists by walking them, or as `<list>`.
- Make the fallback an error or an explicit `<val>` kind, never `Int64`.

### 2.3 Eager declaration bodies (`ce2fa9b`)

The design is right (see §1). The remaining issues are about reporting and
consistency:

- **The error points at the wrong place.** For `macro m => 1 + * 3;`,
  `parse_prefix` accepts `1` as the longest valid prefix, so the user sees
  `expected ';' after declaration body near '+ * 3;'` followed by
  `2:0: invalid declaration`. The real error is at `*`. When the next token
  is not `;`, re-parse the body with `parse()` up to the `;` that follows, or
  report the farthest position the parser reached.
- **Failures are silently counted as success.** `register_guest_macro_stx`
  and `register_static_check_stx` return `void`. If `wrap_for_syntax_stx`
  fails, they return early. That function parses `let NAME = 0 in 0` with the
  *guest* grammar, so it fails for any `#lang` without `let`.
  `apply_decl_cst` then increments `decls_applied` and returns `true`, so the
  macro just isn't defined. Return `bool` from these functions and propagate
  it.
- **The semantics changed without documentation.** A body can no longer use
  syntax declared *later* in the file. That is intended: the previous
  review's follow-up recommended it. Today the only signal is the misleading
  `expected ';'` error. Add one sentence to the README or SKETCH, and a
  negative test.
- **The string-based APIs swallow parse errors.** The `register_guest_*`
  overloads that take a `std::string` are kept for `main.cc` and the smoke
  test. They now parse with `gram->parse(src, "expr")` and silently return on
  failure.

### 2.4 GLR ambiguity (`17e967d`)

**(a) Tier 3 is exponential and caps at depth 8.** `resolve_ambs_tier3`
(`contour_clone.cc:924`) substitutes each alternative of the first `Amb` and
recurses on the rest. That is a full product, with one whole-program IFA run
per leaf. At `depth > 8` it returns the tree with `Amb` nodes still present,
which then fails at the caller:

```
# k copies of `(@n) +` with the scoped_glr.ml `at_rec`/`at_int` rules
k=8   0.85 s   88
k=9   3.0 s    99
k=10  1.7 s    error: unresolved syntax ambiguity for '@n' (0 of 2 alternatives valid)
```

The `k=10` diagnostic is false: both alternatives are valid somewhere.

Independent `Amb` nodes should be resolved independently. Run IFA once with
all alternatives lowered behind a dummy `if`-select, or resolve one `Amb` at a
time while the others are fixed to their first *valid* choice. Then iterate
to a fixpoint. When the depth cap is hit, report that limit explicitly.

**(b) Tier 2 runs guest macros speculatively.** `expander.cc:350` expands
every alternative and keeps the survivors. ROADMAP 5.1 states the rule
"never run guest macros, fresh-scope allocation, or JIT calls
speculatively". Expanding a losing alternative still runs its macros,
including `grammar_add_rule` side effects and JIT compilation. Either add
rollback (snapshot `active_gdef`), or restrict Tier 2 to deciding by the
head's binding without expanding.

**(c) Duplicate derivations become false ambiguities.** Calling a
grammar-installing macro twice adds a second, hygienically renamed copy of
its helper non-terminal. The same input then derives twice, and both
alternatives are discarded:

```
$ ./langwb -e '… install_a(); install_a(); use_a alpha'
langwb: 11:2: unresolved syntax ambiguity for 'use_a alpha' (0 valid expansions)
```

"0 valid expansions" is also wrong here, since each alternative alone
expands to `10`.

**(d) Diagnostics show hygiene-renamed names.** For example,
`alternative 1: paren '(__wb_h_e__ + 10)'`. Print the original source span
instead.

**(e) `wb_ambiguity_fn` uses `p->initial_globals`** (`parse.cc:187`, `:310`)
as a user-data pointer. DParser copies this field into the parse globals of
actions. It is harmless today because there are no actions, but it is
fragile. Alternatives are also keyed by `D_ParseNode*` address, so if DParser
calls the hook more than once for the same node, alternatives are appended
twice.

### 2.5 Grammar hygiene for `grammar_add_rule` (`17e967d`)

`_CG_grammar_add_rule` (`meta_abi.cc:393`) renames a production when it does
not exist *and* has no form macro *at that moment*. Whether a name is public
therefore depends on declaration order:

```
$ ./langwb -e 'macro install_bang => …grammar_add_rule("bang_expr", …)…;
               install_bang(0);
               syntax_rule form bang_expr(_ $x:expr) => "($x * 2)";
               !21'
fail: unresolved identifier: 'bang_expr'
```

The same program with `syntax_rule` before `install_bang(0)` passes. That
order is the one the existing test uses. The macro should state its intent
explicitly. Either use a `grammar_add_public_rule` / `grammar_fresh_nterm`
pair, or make every new non-terminal private unless it is referenced from a
public production in the same call. `rewrite_rhs_nterms` also rewrites
identifiers inside DParser character classes such as `[abc]`. Skip `[...]`.

### 2.6 `match` and quasiquote (`7676c9f`)

- **A `match` with no matching arm returns `0`.** The default case is a
  literal `"0"` (`workbench.cc:779`): `match 5 { 1 => 10, 2 => 20 }` gives
  `0`. Emit a runtime trap, or reject non-exhaustive matches.
- **Record patterns are static field accesses, not tests.**
  `match { x: 1 } { { y: a } => a, _ => 9 }` fails in IFA with `unresolved
  member 'y' of class '__wb_rec_1'`; it does not fall through to `_`. Either
  document that record patterns must match statically, or use IFA's
  `attr_has_field` to drop arms that cannot match.
- **Patterns are limited.** There are no nested patterns
  (`[[a, b] | t]` is a syntax error), no negative literals, and no string
  literals. `head([])` gives `0`. List these in the README.
- **Quasiquote breaks on any string literal.**
  `` `[expr| list_len(["a"]) ] `` fails, because `escape_str`
  (`workbench.cc:934`) emits `\"`. The guest string rule `"[^"]*"` has no
  escapes. Either add escapes to the string literal rule, or build the
  template as syntax rather than re-serialising it.
- **Quasiquote is still text.** `qq_body` is an opaque span. Splices are
  re-parsed from raw text and become `__wb_qq_N_k__` placeholder identifiers,
  so a splice can only appear where an identifier is legal. ROADMAP 6 promised
  "parsed directly against the active `GrammarDef` … zero `__pat_x__`
  identifier-collision risk". The collision risk is now low thanks to a
  counter, but this is the same template mechanism as before. Errors report
  `1:0` instead of the position of the template.

### 2.7 Step 7 checks and contour cloning (`c39f8f2`)

- **`check` is a new reserved word everywhere.** `starts_with_decl`
  (`workbench.cc:310`) matches it textually:
  `def check = 2; check * 21` gave `42` on `origin/main` and now gives
  `invalid declaration`. `syntax_ext` has the same problem. This is the
  open part of the previous review's §2.3: form boundaries and declaration
  detection should come from the grammar.
- **A `check` on an unknown target is accepted silently.**
  `check nosuch => 0; 5` gives `5`. Warn when no core form or call name
  matches.
- **Static checks run only in round 0, and only when `opts.staged` is set**
  (`contour_clone.cc:1022`). Code produced by Stage-1 expansion and by
  splitting is never checked. Document this, or run checks on the final tree.
- **IFA errors still name `__wb_rec_1`**, for example `unresolved member 'b'
  of class '__wb_rec_1'`, even though ROADMAP 4.5 says that is fixed. The
  position is fixed; the type name is not. Print the record's field set
  instead.
- **Positions inside `using syntax … in { … }` are relative to the block.**
  An error inside a region on line 3 reports `<macro:op_inc@1:0>:1:5`. Pass
  the block's offset into `parse()`.

### 2.8 Minor

- `grammar_def.h:16` still gives `"$binary_op_left 1"` as the example
  modifier, and `tests/run_tests.sh:234` still uses it. Say which form is
  supported now that rule priority drives operator priority.
- `step7_checks.ml` dropped its parentheses after the precedence fix. That
  is good. The commit should also have added the two `origin/main`
  precedence failures as tests, which it did (`precedence_*`).
- `QuietStderr` redirects the process-wide `fd 2` while probing Tier-3
  alternatives. That is fine for the CLI, but unsafe once the workbench is
  used as a library or from more than one thread.

## 3. Recommended order

1. Fix the closure crash and arity bugs (§2.1a–c) and add them as tests.
   Upstream the `ifa/` edits.
2. Fix `eval_value` classification (§2.2).
3. Make Tier-3 linear in the number of `Amb` nodes, and make the cap
   explicit (§2.4a). Stop Tier 2 from running macros speculatively (§2.4b).
4. Propagate registration failures, and improve the error position for
   declaration bodies (§2.3).
5. Use grammar-driven declaration detection, so that `check`, `hook` and the
   other keywords are no longer reserved globally (§2.7). This is the
   remaining half of the previous review's §2.3.
