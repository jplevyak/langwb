## 1. Assessment of the Step 11 implementation

Step 11 accomplished its goal cleanly and adhered strictly to the §6.2 C++
change policy:

- **Honest replaced-grammar dogfood (`examples/langs/mlite.lang`):** Replacing
  `expr` and `stmt` with `:=` forced every Phase-1 helper, macro, Stage-1
  specializer, static check, hook, and transfer function after line 46 to be
  written in MLite itself, surfacing 23 concrete friction items (`FL-1..FL-23`)
  without adding any MLite-specific C++.
- **Complete feature & tooling coverage:** Nothing was cut under §6.1. All four
  stdlib modules (`option`, `result`, `list`, `assert`) and all four target
  programs (`expr_eval`, `wordcount`, `graph_cycle`, `aot_cli`) run identically
  under JIT and standalone AOT builds (invoked from an external working
  directory), and are exercised through `--lsp` (`publishDiagnostics`, `hover`,
  and cross-file `definition`).
- **Well-targeted engine fixes:**
  - **Uniform operator-priority productions (`cfcd9a4`):** Caught and documented
    that DParser rule-level `$left N` and operator-level `$binary_op_left M` do
    not mix symmetrically (`2 * 10 |> 3` grouped as `2 * (10 |> 3)`), motivating
    uniform operator-priority productions across `mlite.lang`.
  - **Pass-2a `import_alias` + ready-capture lambda lowering (`995be0a`):**
    Cleanly initializes imported value and function aliases (including
    re-exports and closures whose captured defs are already initialized) before
    the importer's top-level `val`/`def` initializers run, while preserving
    `fn_arity`.
  - **Right-recursive `let_tail` (`645599a`):** Multi-binding `let` (`val` and
    `fun` interleaved) is expressed purely with `core(let)` / `core(letrec)`
    annotations and zero macro overhead.
  - **`is_monotone_extension` subsumption (`86685b4`):** Accurately recognizes
    constant-to-base-type widening (`{9}` → `{int64}`) without weakening debug
    monotonicity checks against constant-to-different-constant bugs (since
    `after->v[j]->sym == cs->sym->type` only holds when `after->v[j]->sym` is
    the non-constant type symbol).

## 2. Concrete findings

### 2.1 [Medium] `for` loop in `mlite.lang` shadows outer `i` in `lo` and evaluates `hi` before `lo`

In `examples/langs/mlite.lang:206-209`:

```ml
syntax_rule form for_e(_, $i:ident, _, $lo:expr, _, $hi:expr, _, $body:block, _) =>
  let val hi = $hi in
    do var $i = $lo; while $i <= hi do $body; $i := $i + 1 end end
  end;
```

Two issues arise from placing `var $i = $lo` inside `do ... end` inside
`let val hi = $hi`:

1. **Outer variable shadowing in `$lo`:** `var $i = $lo` is a
   `CoreFormKind::Define` inside `CoreFormKind::Seq`. Pass 1 of `Seq` binds `$i`
   across the entire `do ... end` block *before* resolving `$lo`, so an outer
   binding with the same name cannot be referenced in `$lo`:
   ```sh
   ./langwb -e $'#lang mlite\nval i = 5; var s = 0; for i = i + 1 to 8 do s := s + i end; s'
   # <macro:for_e@2:22>:2:26: error: 'i' is used before assignment on every path
   ```
2. **Reversed bound evaluation order:** `$hi` is evaluated before `$lo`:
   ```sh
   ./langwb -e $'#lang mlite\nvar order = 0; fun step(k) = do order := order * 10 + k; k end; for i = step(1) to step(2) do 0 end; order'
   # prints 21 instead of 12
   ```

**Suggested fix:** Use M5's multi-binding `let` so both bounds are evaluated
left-to-right in the outer scope before `var $i` is introduced:

```ml
syntax_rule form for_e(_, $i:ident, _, $lo:expr, _, $hi:expr, _, $body:block, _) =>
  let val lo = $lo; val hi = $hi in
    do var $i = lo; while $i <= hi do $body; $i := $i + 1 end end
  end;
```

### 2.2 [Medium] FL-12 (`lang_base_`) fails when `load_lang` is called on a root `Workbench` (`--repl`)

In `src/workbench/workbench.cc:198-199`, `lang_base_` is only set in the
cloning constructor:

```cpp
lang_base_(parent.lang_base_ ? parent.lang_base_ : &parent)
```

When `Workbench::load_lang` is called directly on a root `Workbench` (as
`--repl` does on `#lang mlite` in `src/cli/main.cc:251-258`, or via the C++
embedding API), the root `Workbench` is mutated in place while its `lang_base_`
stays `nullptr`. Any subsequent evaluation that imports a `#lang mlite` module
sets `session.lang_base_ = &wb` (which already has `mlite` loaded) and reloads
`mlite.lang` on top of itself:

```sh
printf '#lang mlite\nval x = 0; import "examples/mlite/std/option.mlite"; unwrap_or(Some(42), x)\n:q\n' | ./langwb --repl
# langwb: production 'eq_op' already exists; use '+=' to extend or ':=' to replace it
```

Additionally, in `src/cli/main.cc:260-266`, `Workbench::starts_with_decl(sv)`
matches `import`, routing lines starting with `import "foo.mlite"; expr` to
`wb.apply_decl(sv)` (which does not handle `decl_import` and fails with
`error: invalid declaration`).

**Suggested fix:**
- Store `std::shared_ptr<const Workbench> lang_base_;` and, at the top of
  `Workbench::load_lang` when `loading_lang_depth_ == 0 && !lang_base_`,
  snapshot `lang_base_ = std::shared_ptr<const Workbench>(new Workbench(*this, true));`
  before mutating `*this`.
- In `run_repl` (`src/cli/main.cc:260`), exclude `import` from the single-decl
  `wb.apply_decl(sv)` branch (or only take `apply_decl` when `sv` has no
  trailing forms after the declaration) so `import "..."; expr` reaches
  `wb.eval_value`.

### 2.3 [Low–Medium] FL-23 LSP `textDocument/definition` emits unencoded `file://` URIs

In `src/workbench/lsp.cc:607-612`:

```cpp
if (binder->file) {
  std::error_code ec;
  std::filesystem::path abs = std::filesystem::absolute(binder->file, ec);
  target_uri = "file://" + (ec ? std::string(binder->file) : abs.lexically_normal().string());
}
```

`uri_to_path` at the top of `src/workbench/lsp.cc` percent-decodes incoming
`file://` URIs, but `target_uri` concatenates the raw filesystem path without
percent-encoding spaces or reserved URI bytes (`%`, `#`, `?`). Reproducible when
the workspace directory contains a space:

```text
{'uri': 'file:///private/var/folders/.../langwb space wf5gf1md/lib.ml', ...}
```

**Suggested fix:** Add a symmetric `path_to_uri(const std::filesystem::path &)`
helper that percent-encodes any byte outside RFC 3986 unreserved + `/`.

### 2.4 [Low] FL-22 syntax errors inside `using syntax` still report block-relative `1:C`

In `src/workbench/workbench.cc:232-250`:

```cpp
parse::CstNode *body_cst = ext_gram->parse(trim_ws(body_src), "expr");
...
if (body_node && body_node->line > 0) {
  int line = body_node->line, col = body_node->col + 1;
  ...
  advance_line_col(lead, line, col);
  offset_syntax_loc(stx, line - 1, col);
```

Type, static-check, and LSP positions inside `using syntax` are now properly
offset, **but** if `ext_gram->parse` itself fails with a syntax error, it still
uses the default `line_offset = 0, col_offset = 0`:

```sh
./langwb -e $'#lang mlite\nval a = 1;\nval b = 2;\nusing syntax power in {\n  2 ** + 3\n}'
# langwb: 1:3: syntax error   (actual location is 5:7)
```

**Suggested fix:** Compute `(line, col)` before calling `ext_gram->parse` and
pass `/*quiet=*/false, line - 1, col` into `ext_gram->parse`.

### 2.5 [Low] `find_node_at` in `src/workbench/lsp.cc` still uses last-child order on non-terminal fallback

`32f18d3` (`FL-21`) updated `find_annotated_at` (`textDocument/hover`) to pick
the narrowest node covering `(line, col)`, preventing relocated template nodes
from shadowing user tokens. `find_node_at` (`src/workbench/lsp.cc:288-309`,
used by `textDocument/definition`) skips `node->file != nullptr` as well, but
still overwrites `best = found` in child order rather than comparing
`node->text.size()`. In practice `prefer_terminal = true` avoids the macro
template `App` node (since `stx_copy_loc` only relocates the non-terminal), but
selecting the narrowest match in `find_node_at` too would keep `hover` and
`definition` consistent when macros splice or duplicate spans.
