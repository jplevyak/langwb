Top findings:

1. **FL-4's `reject_reserved` rejects *any* `D_SYMBOL_REGEX` matching a reserved
   word, breaking `using syntax` (`raw_block`) and quasiquotes (`qq_body`)
   (§2.1).** Valid MLite expressions such as
   `using syntax power in { (fn(x) => x ** 2)(3) }` or
   `using syntax power in { if(true) then 2 ** 3 else 0 }` fail with
   `syntax error: 'fn' is a reserved keyword` / `'if' is a reserved keyword`.
   `GrammarDef::extend` also drops `extension.reserved_`.
2. **LSP `build_doc_index` drops every warning (`Severity::Warning`) whenever
   evaluation succeeds (§2.2).** Passing
   `res.ok ? std::vector<diag::Diagnostic>{} : res.diagnostics` to
   `format_diagnostics_json` suppresses Step 12 M3's own FL-2 priority warnings,
   unused `check` warnings, undefined `export` warnings, and shadow warnings on
   every valid document in `langwb --lsp`.
3. **Display-name & guest-wording gaps (§2.3):**
   - `bridge.cc` omits `__wb_recfn_<f>_<n>` (handled in `lsp.cc`), so MLite
     `let fun` and minilang `rec` functions still leak `__wb_recfn_f_1` in type
     error messages (`let fun f(x) = x + 1 in f + 2 end`).
   - Non-literal `if` / `while` conditions (`val x = 1; while x do 0 end`) fall
     through `guest_message` and still report raw IFA
     `illegal primitive argument type 'x' illegal: int64`.
   - MLite's `or` / `and` macros check only the left operand as `bool`, so
     `true or 1` (`=> true`) and `(false or 5) + 1` (`=> 6`) are accepted
     without error.
4. **Incremental `make` fails at link time when `dparser/` sources change
   (§2.4).** `Makefile` tracks `IFA_SRCS` for `libifa_gc.a` but has no
   `dparser/*.c` / `dparser/*.h` prerequisites on `dparser/libdparse_gc.a`.

## 1. Assessment of the Step 12 implementation

Step 12 was executed cleanly, milestone by milestone (`M0` → `M1` → `M2` → `M3`
→ `M4`), following the plan's baseline-first discipline:

- **Zero-regression M0 plumbing (`src/diag/`, `0079fc4`, `704d96b`, `f894af1`,
  `8cd2ce3`, `845688e`):** Routing ~115 diagnostic sites through `diag::Sink`
  while keeping M0's CLI text byte-identical gave a clean separation between
  plumbing and wording. Both subtree hooks (`d_set_fail_handler` /
  `d_set_warn_handler` in `dparser/util.c` with `dparser/test_fail_handler.c`,
  and `show_violations_each` in `ifa/analysis/fa_debug.cc`) are minimal,
  upstreamable, and free of `langwb` policy.
- **Cascaded `NOTYPE` elimination and provenance chains (`8ef44c3`, `40b3ae2`,
  `c9cf936`):** Combining IF1 PNode/upstream-AVar checks with `SyntaxObj` span
  containment in `is_consequential_notype` eliminates cascaded `expression has
  no type` noise while keeping standalone `NOTYPE` errors (`def f = fn(x) =>
  f(x); f(1) + 2`). `SyntaxObj::synthetic` + `outer_origins` cleanly relocates
  macro-template nodes to call sites and renders multi-step expansions (`**` →
  `fast_pow`) as ordered `note:` / `relatedInformation` chains.
- **Shared `#lang` snapshots (`c4ad1d9`) and parallel test runner (`a6b2bb9`):**
  Caching per-process `#lang` snapshots on `lang_base_` (with `LangMacroReg`
  re-scoping per imported module) cut multi-module MLite compilation time roughly
  in half without breaking private ADT constructor hygiene.
- **Process-isolated LSP (`4388707`, `27a726c`):** Moving `langwb --lsp` to a
  single-threaded router that never constructs a `Workbench` or initializes
  LLJIT in-process — bracketing worker `fork()`s with
  `GC_atfork_prepare`/`parent`/`child` and serializing `DocIndex` over a pipe
  with edit coalescing and `SIGKILL` cancellation — cleanly isolates infinite
  macro loops and crashes.

## 2. Concrete findings

### 2.1 [High] FL-4 `reject_reserved` rejects `raw_atom` / `qq_atom` regex terminals inside `using syntax` and quasiquotes, and `GrammarDef::extend` drops `reserved_`

In `src/parse/parse.cc:348-382`, `DynamicGrammar::reject_reserved` rejects any
reduction containing a `D_SYMBOL_REGEX` terminal whose matched text is in
`reserved_`:

```cpp
if (kind == D_SYMBOL_REGEX) {
  const char *s = c->start_loc.s;
  if (!s || !c->end || c->end <= s) return false;
  return st->gram->is_reserved(std::string_view(s, static_cast<size_t>(c->end - s)));
}
```

However, scannerless raw-body rules in `src/workbench/workbench.cc` also use
`D_SYMBOL_REGEX` terminals to capture uninterpreted text chunks between
balanced delimiters:

- `raw_atom : "[^(){}\"]+"` (`src/workbench/workbench.cc:1187`, used by
  `using syntax <ext> in { ... }` in both minilang and `mlite.lang:322`);
- `qq_atom : "[^\\[\\](){}\"]+"` (`src/workbench/workbench.cc:1258`, used by
  quasiquote `` `[nt | ... ] ``).

Whenever a reserved keyword inside `using syntax` or a quasiquote is immediately
followed by `(`, `)`, `{`, `}`, `[`, `]`, or `"` (with no trailing space before
the delimiter), `raw_atom` / `qq_atom` matches the exact keyword slice and
`reject_reserved` aborts the parse, causing `blame_reserved` to blame the valid
keyword:

```sh
./langwb -e $'#lang mlite\nusing syntax power in { (fn(x) => x ** 2)(3) }'
# <input>:2:25: error: syntax error: 'fn' is a reserved keyword

./langwb -e $'#lang mlite\nusing syntax power in { if(true) then 2 ** 3 else 0 }'
# <input>:2:24: error: syntax error: 'if' is a reserved keyword

./langwb -e $'grammar { reserve \'let\', \'in\', \'fn\'; };\nmacro m => `[expr | (fn(x) => x)(42)];\nm()'
# <input>:3:21: error: syntax error: 'fn' is a reserved keyword
```

In addition, `GrammarDef::extend(const GrammarDef &extension)` in
`src/parse/grammar_def.cc:55-62` copies `extension.productions_` and silently
drops `extension.reserved_`.

**Suggested fix:** Skip `raw_atom` / `qq_atom` (or check `is_reserved` only on
`D_SYMBOL_REGEX` terminals whose matched text consists of identifier characters
*and* whose symbol name is not a negated-delimiter raw chunk such as
`"[^(){}\"]+"` / `"[^\\[\\](){}\"]+"`, or record non-raw regex symbols when
compiling the grammar), and copy `extension.reserved_` in `GrammarDef::extend`
via `add_reserved`.

### 2.2 [High] LSP `build_doc_index` discards all warnings when `res.ok` is true

In `src/workbench/lsp.cc:491-495`:

```cpp
DocIndex build_doc_index(const std::string &uri, const InspectResult &res) {
  DocIndex idx;
  idx.diagnostics_json =
      format_diagnostics_json(uri, res.ok ? std::vector<diag::Diagnostic>{} : res.diagnostics);
```

Although `format_diagnostics_json` (`src/workbench/lsp.cc:309-311`) maps
`diag::Severity::Warning` to LSP severity `2`, `build_doc_index` replaces
`res.diagnostics` with `{}` whenever `res.ok` is `true`. Every warning on a
valid document is therefore lost in `--lsp`, including:

- Step 12 M3's own FL-2 priority warnings (`GrammarDef::report_priority_warnings`,
  `src/parse/grammar_def.cc:293`, which runs only after `gram->compile` succeeds);
- unused `check` target warnings (`src/workbench/contour_clone.cc:1190`);
- undefined `export` and shadowed `import` warnings
  (`src/workbench/workbench.cc:2966, 3219`);
- DParser `d_warn` grammar warnings (`src/parse/parse.cc:319`).

Reproducer:

```sh
python3 - <<'PY'
import json, os, subprocess

def frame(o):
    s = json.dumps(o)
    return f"Content-Length: {len(s)}\r\n\r\n{s}".encode()

def read_msg(fd):
    hdr = b""
    while b"\r\n\r\n" not in hdr:
        hdr += os.read(fd, 1)
    cl = int(hdr.decode().split("Content-Length:")[1].split("\r\n")[0].strip())
    body = b""
    while len(body) < cl:
        body += os.read(fd, cl - len(body))
    return json.loads(body.decode())

doc = (
    "grammar expr += pipe_e core(passthrough);\n"
    "grammar pipe_e : expr '|>' expr $left 1;\n"
    "syntax_rule form pipe_e($a:expr, _, $b:expr) => $b($a);\n"
    "check nonexistent_fn => 0;\n"
    "42\n"
)
p = subprocess.Popen(["./langwb", "--lsp"], stdin=subprocess.PIPE, stdout=subprocess.PIPE)
p.stdin.write(frame({"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}))
p.stdin.write(frame({"jsonrpc":"2.0","method":"textDocument/didOpen","params":{
    "textDocument":{"uri":"file:///tmp/warn.ml","languageId":"ml","version":1,"text":doc}
}}))
p.stdin.flush()
read_msg(p.stdout.fileno())
print(read_msg(p.stdout.fileno()))  # -> {'diagnostics': []} (both warnings lost)
p.stdin.write(frame({"jsonrpc":"2.0","id":2,"method":"shutdown","params":{}}))
p.stdin.write(frame({"jsonrpc":"2.0","method":"exit","params":{}}))
p.stdin.flush()
p.wait(timeout=5)
PY
```

**Suggested fix:** Pass `res.diagnostics` to `format_diagnostics_json(uri, res.diagnostics)`
even when `res.ok` is `true` (filtering out any `Severity::Error` if `res.ok` is
`true`, though no error should be emitted on a succeeding evaluation). Also note
that `GrammarCache::compile_or_get` (`src/parse/grammar_def.cc:274-293`) and
`Workbench::lang_snapshot` (`src/workbench/workbench.cc:458-466`) emit FL-2
warnings only on cache misses: forked LSP workers start cold today so they see
them once per evaluation, whereas a second evaluation in `--repl` (or a future
pre-forked zygote) skips `report_priority_warnings()` on cached grammars.

### 2.3 [Medium] Guest-term gaps: `__wb_recfn_` leaks in type errors, non-literal `if`/`while` conditions emit raw IFA wording, and MLite `and`/`or` skip right-operand bool checks

Three closely related gaps remain in M2's guest-term translation:

1. **`__wb_recfn_<f>_<n>` leaks in `bridge.cc` (§6 Criterion 2):** Rather than
   sharing a single display-name helper (§2.3.3), `src/workbench/lsp.cc:408-419`
   and `src/ifa_bridge/bridge.cc:2705-2728` maintain separate implementations.
   `lsp.cc:415` strips `__wb_recfn_` (`let fun` in MLite, `rec` in minilang,
   lowered at `src/ifa_bridge/bridge.cc:1505`), while `bridge.cc:2705-2728` only
   rewrites `__wb_deffn_` and `__wb_fn_`:

   ```sh
   ./langwb -e $'#lang mlite\nlet fun f(x) = x + 1 in f + 2 end'
   # <input>:2:26: error: invalid operand to '+': __wb_recfn_f_1

   ./langwb -e $'#lang mlite\ntype Opt = None | Some(v);\nlet fun f(x) = x + 1 in case f of None => 0 | Some(v) => v end end'
   # <input>:3:24: error: value matched by 'case' must be Opt, got __wb_recfn_f_1
   ```

2. **Non-literal `if` and `while` conditions fall back to raw IFA prose:**
   `name_literal_condition` (`src/ifa_bridge/bridge.cc:825-836`) intentionally
   skips non-constant condition symbols (`!cond->is_constant`) so `isinstance`
   narrowing across `IF` is preserved. When `x` is a variable, `pv.node` in
   `guest_message` (`src/ifa_bridge/bridge.cc:2781-2806`) is the user's
   `CoreFormKind::If` / `CoreFormKind::While` node (`description` empty,
   `user_construct` empty, `operator_name` empty because `Code_IF` / `Code_LOOP`
   is not `Code_SEND`), so `guest_message` returns `false`:

   ```sh
   ./langwb -e $'#lang mlite\nval x = 1;\nwhile x do 0 end'
   # <input>:3:0: error: illegal primitive argument type 'x' illegal: int64

   ./langwb -e $'#lang mlite\nval x = 1;\nif x then 10 else 20'
   # <input>:3:0: error: illegal primitive argument type 'x' illegal: int64
   ```

   Checking `c->kind == Code_IF` / `Code_LOOP` (or `node->core.kind ==
   CoreFormKind::If` / `While`) inside `guest_message` produces
   `condition of 'if' must be bool, got int64` / `condition of 'while' must be
   bool, got int64` without inserting an extra `if1_move`.

3. **MLite `or` / `and` do not require a boolean right operand
   (`examples/langs/mlite.lang:206-217`):** `or_e` expands to
   `if __a__ then true else __b__` and `and_e` to
   `if __a__ then __b__ else false` with `"left operand of 'or'"` /
   `"left operand of 'and'"`. `__b__` is never checked to be `bool`, so
   `#lang mlite\ntrue or 1` evaluates to `true`, `(false or 5) + 1` evaluates
   to `6`, and `not (true and 5)` blames `operand of 'not': int64` rather than
   `right operand of 'and'`. Wrapping `__b__` in a described
   `if __b__ then true else false` makes both operands symmetrically `bool`.

### 2.4 [Medium] Incremental `make` fails to rebuild `dparser/libdparse_gc.a` when `dparser/` sources change

`Makefile:106-108` depends on `IFA_SRCS` so edits under `ifa/` rebuild
`libifa_gc.a` automatically, whereas `Makefile:93-95` has no source
prerequisites on `$(DPARSER_DIR)/libdparse_gc.a`:

```makefile
$(DPARSER_DIR)/libdparse_gc.a:
	$(MAKE) -C $(DPARSER_DIR) D_USE_GC=1 D_DEBUG=$(DEBUG) D_OPTIMIZE=$(OPTIMIZE) \
		libdparse_gc.a libmkdparse_gc.a version.o
```

In an already-built tree, pulling `0079fc4` (`dparser/util.c`, `dparser/util.h`)
and running `make` recompiles `src/parse/parse.o` against the updated header and
then fails to link against the stale `dparser/libdparse_gc.a`:

```
Undefined symbols for architecture arm64:
  "_d_set_fail_handler", referenced from: langwb::parse::DynamicGrammar::compile(...)
  "_d_set_warn_handler", referenced from: langwb::parse::DynamicGrammar::compile(...)
```

**Suggested fix:** Add
`DPARSER_SRCS := $(wildcard $(DPARSER_DIR)/*.c $(DPARSER_DIR)/*.h)` as a
prerequisite of `$(DPARSER_DIR)/libdparse_gc.a` (matching `IFA_SRCS`).

## 3. Minor / polish items

1. **`assert_single_threaded()` in `--lsp` is a no-op on macOS
   (`src/workbench/lsp.cc:718-735`):** It reads `/proc/self/status` and returns
   immediately when `fopen` fails. Because `/proc` does not exist on Darwin —
   the primary platform where post-`fork` Mach-port / thread state is hazardous
   (`docs/STEP12_DIAGNOSTICS.md` §2.5) — adding an `#ifdef __APPLE__` branch
   using `task_threads(mach_task_self(), &list, &count)` (deallocating the
   returned Mach thread rights and VM buffer before asserting `count == 1`)
   makes the debug check effective on macOS as well as Linux.
2. **LSP `word_at` constructor fallback triggers inside comments, strings, and
   record field names (`src/workbench/lsp.cc:546-557`):** When no AST token in
   `idx.defs` covers the cursor, `definition_result` falls back to
   `word_at(text, line, col)` against `idx.ctors`. Invoking
   `textDocument/definition` on `Some` inside `# Some comment`, `"Some string"`,
   or `{ Some: 1 }` therefore jumps to `type Opt = None | Some(v)`. Skipping
   positions inside `#` comments or string literals (or indexing pattern
   constructors directly during CST/macro expansion) avoids false jumps.
3. **Dead / unguarded non-staged `out_top_fields` analysis probe
   (`src/workbench/contour_clone.cc:1232-1239`):** When `!opts.staged &&
   out_top_fields`, `prepare_staged_syntax` runs `analyze_syntax` without a
   `DiscardingSink` (contrary to `docs/STEP12_DIAGNOSTICS.md` §2.2) and ignores
   its return value, causing `compile_and_jit_value` / `compile_to_llvm_ir` to
   emit every diagnostic twice on non-staged calls. Moreover, both callees now
   ignore `record_fields` (`(void)record_fields;` at
   `src/ifa_bridge/bridge.cc:3240, 3360`), so `out_top_fields` / `top_fields`
   can be deleted outright.
4. **`ScopedMainFile` allocates a new `std::string` per call without
   deduplication (`src/diag/diagnostic.cc:57-62`):** Even when `path` is empty
   or repeated (e.g. in `--repl` or repeated `eval_*` calls),
   `names.push_back(new std::string(path))` leaks a fresh `std::string`. It can
   delegate to `syntax::SyntaxObj::intern_file(path)` (`src/syntax/syntax.cc:215`)
   when `!path.empty()`.
