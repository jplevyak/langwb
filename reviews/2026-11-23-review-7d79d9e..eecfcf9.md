# langwb review — 2026-11-23, `7d79d9e..eecfcf9`

This is a delta review of the four commits since `7d79d9e`:

| commit | subject |
|---|---|
| `65139a8` | Follow up 2026-11-23 review: hygiene, module diagnostics, error wording, closure inlining fix |
| `5f2f592` | Constructor equality, reserved `_tag`, import placement hint, documented limits |
| `83b8ef4` | Print records and ADT values through per-type functions with cycle detection |
| `eecfcf9` | Fix field assignment through IFA-split record classes (`WbSymbol::copy`) |

The build has no warnings. `make test` passes: 31/31 `--smoke`, 12/12
`examples/minilang/*.ml`, and 250/250 cases in `tests/run_tests.sh` (+46 new
tests since `7d79d9e`). Every finding below was reproduced against `eecfcf9`
with the quoted commands.

The top four:

1. **Memory-safety crash (SIGSEGV) printing a union of IFA-split clones of the
   same record or ADT variant class (§2.1).**
   `type L = Nil | Cons(h, t); if runtime_val(1) == 1 then Cons(1, Nil) else Cons("a", Nil)`
   crashes (`exit=139` in AOT; `evaluation failed` in JIT), and the same crash
   happens for plain records (`def mk = fn(x) => { a: x }; if runtime_val(1) == 1 then mk(1) else mk("hi")`).
   When no IF1 `sym_period` reads the disagreeing field on the union, IFA gives
   both clones the same classtag global (`@"_CG_type_L::Cons_82"`). The printer's
   `Type_SUM` dispatch compares against that tag twice, so the first arm always
   matches and reads `1` as a `const char *` pointer.
2. **An ADT variant with a payload field named `_tag` silently drops its payload
   and breaks `==` (§2.2).** `type Box = B(_tag); B(42)` prints `B` instead of
   `B(42)`, and `B(1) == B(2)` returns `true`. `decl_type` does not forbid
   `_tag` as a field name, while `is_nullary_variant_class` and
   `get_record_printer` treat any single `_tag` field as the synthesized nullary
   tag.
3. **Exported macros cannot call private helper macros in the same module
   (§2.3).** `decl_scope_` gives exported macros hygienic access to private
   `def`s (and `export grammar;` exports form macros cleanly), but unexported
   helper `syntax_rule`s are not visible when an exported macro expands in an
   importer (`unbound identifier 'priv_inc'`).
4. **Un-upstreamed `ifa/` subtree edits now span 9 files (+69/−12 since
   `9d9fc47`) (§2.5).** Two of these (`clone_reset()` and `inline.cc`'s
   `is_simple_closure_create` MOVE-chain fix) are standalone IFA bug fixes;
   `dead.cc`, `codegen_common.cc`, and `inline.cc` affect all IFA front ends
   and need a `pyc` regression run before upstreaming.

## 1. Assessment of the four commits

Overall this is a strong, well-tested set of commits that closes almost every
remaining ergonomic and correctness gap from the earlier 2026-11-23 reviews:

- **`WbSymbol::copy()` (`eecfcf9`)** fixes a real root-cause bug in the IFA
  bridge: copying the underlying `Sym` via `sym->copy()` instead of building a
  bare `new Sym()` preserves `has` on IFA-split record classes, fixing nested
  field assignment (`c.t.h = 5`) and multi-site record constructors (`mk(1)` /
  `mk("hi")` with mutation).
- **Per-type `_wb_print_<id>(ptr)` with cycle detection (`83b8ef4`)** is a
  clear architectural upgrade over fixed-depth inlined printing. Recursive ADTs
  print past depth 6 (up to 1000 levels, stopping cleanly with `...`), and both
  self-cycles (`N(<cycle>)`) and mutual cycles (`Box(Box(<cycle>))`) terminate
  cleanly in JIT and AOT without breaking shared acyclic values.
- **`ifa/optimize/inline.cc` (`65139a8`)** fixes a genuine IFA bug where
  `INLINE_CLOSURE` killed a closure creation whose value reached multiple call
  sites through a `Code_MOVE` chain (`let f = fn(x) => x + s in f(1) + f(2)`).
- **Diagnostics & hygiene (`65139a8`, `5f2f592`)** are much cleaner:
  `SyntaxObj::file` prefixes module errors with their file path; `decl_scope_`
  unifies macro hygiene across `syntax_rule`, `macro`, `stage1_macro`,
  `syntax_ext`, and `export grammar;`; `classify_wb_type` derives
  `EvalValue::Kind` from the IFA type instead of sniffing output text;
  `Makefile` tracks `IFA_SRCS` so `ifa/` edits rebuild `libifa_gc.a`; and
  nullary constructor equality (`x == None`, `c == Red`) works cleanly.

## 2. Findings

### 2.1 SIGSEGV printing a union of IFA-split clones of the same class (`83b8ef4` / `7d79d9e`)

In `emit_llvm_wb_value` (`src/ifa_bridge/bridge.cc:2209-2240`), a `Type_SUM`
whose members are all `Type_RECORD`s dispatches at runtime by comparing the
object's slot-0 classtag against `llvm_emit_classtag_eq(m, v)` for each member
`m`.

That assumes distinct members `m` in `ty->has` have distinct classtags. When
IFA splits one record or variant class into two creation sets with different
field types (e.g. `Cons(1, Nil)` with `h: int64` and `Cons("a", Nil)` with
`h: string`), IFA's `cg_plan_concrete_tags` only splits their classtag family
if an IF1 `sym_period` reads the disagreeing field on the union. Printing goes
through `wb_emit_val` / `print` (a `RegisteredPrim`), not `sym_period`, so both
clones stamp the **same** classtag global:

```
$ ./langwb -e 'type L = Nil | Cons(h, t); if runtime_val(1) == 1 then Cons(1, Nil) else Cons("a", Nil)'
langwb: evaluation failed              # AOT binary exits with 139 (SIGSEGV)

$ ./langwb -e '{ def mk = fn(x) => { a: x }; if runtime_val(1) == 1 then mk(1) else mk("hi") }'
langwb: evaluation failed              # same crash on plain records
```

Inspecting `--emit-llvm` confirms both constructors store `@"_CG_type_L::Cons_82"`
and the union printer emits two identical `icmp eq ptr %wb_tag, @"_CG_type_L::Cons_82"`
checks. The first arm (here the `string` clone) always matches `Cons(1, Nil)`
and passes `(const char *)1` to `_CG_wb_emit_str`.

**Fix options:**

- **Check tag uniqueness in `emit_llvm_wb_value` (fast, safe):** Before emitting
  the `Type_SUM` classtag dispatch, check whether any two members `m_i, m_j` in
  `rec_members` share the same `cg_tag_name(m)` (or same `llvm::GlobalVariable*`
  from `get_classtag_global`). If two members collide on tag, do not dispatch
  between them — fall back to `<union>` (or only dispatch unique-tag members
  and emit `<union>` for colliding families).
- **Split classtags for `reads_fields` unions in IFA (complete):** Teach
  `cg_plan_concrete_tags` (`ifa/codegen/codegen_common.cc:2745`) to treat a
  `reads_fields` prim argument of `Type_SUM` like a field read across all
  members, so `Cons(1, Nil)` and `Cons("a", Nil)` get distinct concrete tags
  and both print accurately (`Cons(1, Nil)` and `Cons("a", Nil)`).

The first fix prevents the crash immediately; the second makes heterogeneous
record/ADT unions print accurately.

### 2.2 Reserved `_tag` field name is not rejected in `type` declarations (`5f2f592`)

`resolve_node` (`src/ifa_bridge/bridge.cc:690`) now rejects `x._tag = ...`
because `_tag` is reserved for the synthesized field of nullary ADT variants.
However, `decl_type` (`src/workbench/workbench.cc:855`) still allows a user to
declare a payload field named `_tag`:

```
$ ./langwb -e 'type Box = B(_tag); B(42)'
B                                      # payload 42 silently dropped
$ ./langwb -e 'type Box = B(_tag); B(1) == B(2)'
true                                   # treated as a nullary variant!
```

Both `is_nullary_variant_class` (`workbench.cc:1353`) and `get_record_printer`
(`bridge.cc:2161`) identify nullary variants by checking whether a field is
named `"_tag"`. Reject `_tag` as a field name in `decl_type` with a clear
error.

Also note a minor inconsistency on plain records: `{ _tag: 7 }` is accepted and
prints `{ _tag: 7 }`, while `let r = { _tag: 1 } in { r._tag = 2; r._tag }` is
rejected with `cannot assign to '_tag': it is reserved for the variant of ADT values`.
Either reserve `_tag` in record literals too, or only reject `_tag` assignment
when the object is an ADT (or document `_tag` as reserved on all records).

### 2.3 Exported macros calling private helper macros (`65139a8`)

`decl_scope_` ensures exported macros hygienically resolve private `def`s in
their defining module, and `export grammar;` exports form macros for exported
productions. However, an exported `syntax_rule` that expands into a call to a
private (unexported) `syntax_rule` in the same module fails in the importer:

```
$ cat m.ml
syntax_rule priv_inc($x:expr) => ($x + 1);
syntax_rule pub_inc2($x:expr) => priv_inc(priv_inc($x));
export pub_inc2;

$ ./langwb -e 'import "m.ml"; pub_inc2(40)'
langwb: 1:0: unbound identifier 'priv_inc' (expanded from 'pub_inc2' at 1:32)
```

Because `pub_inc2` is copied into the importer's `stage0_` expander, its
expansion runs in the importer's macro environment where `priv_inc` does not
exist. Either expand macro templates against the defining module's `stage0_`
(e.g. a module-scoped macro table) or document that helper macros referenced by
exported macros must also be exported.

### 2.4 Smaller issues

- **`lsp.cc` `parse_diag_loc` for digit-prefixed module filenames (`65139a8`):**
  `src/workbench/lsp.cc:360` distinguishes a bare `L:C` diagnostic from an
  imported-module diagnostic (`<file>:L:C`) by checking
  `std::isdigit(rest.front())`. An imported module whose filename starts with a
  digit (e.g. `1mod.ml:2:5: ...`) passes `isdigit('1')` and gets parsed as line
  1 / col 2 of the importing document instead of being pinned to the top of the
  document. Check that every character before the first `:` is a digit.
- **`emit_adt_variant_eq` pointer comparison (`5f2f592`):**
  `src/workbench/workbench.cc:1421` uses `std::find(ms.begin(), ms.end(), m)`
  to test whether a nullary variant `m` is in `ms`. This works today because
  nullary variants only hold `_tag = 0` and IFA never splits them into multiple
  `Sym`s, so every `None` shares one `Sym *`. Comparing by `cg_tag_family` (or
  `m->name`) would make it immune to future splitting.
- **`syntax_error_hint` false-positive boundary (`5f2f592`):**
  `src/parse/parse.cc:359` checks whether the token immediately preceding the
  syntax error is `import`. That works cleanly for `{ import "x"; 1 }` and did
  not false-trigger on `let import = 1 in import + * 2` (because `+` precedes
  `*`), though `let import = 1 in import 2` would still emit the hint. Acceptable
  for a heuristic hint.

## 3. Recommended order

1. Fix the `Type_SUM` split-clone classtag collision crash in
   `emit_llvm_wb_value` (§2.1) — either guard colliding tags immediately or
   teach `cg_plan_concrete_tags` about `reads_fields` unions.
2. Reject `_tag` as a field name in `decl_type` (§2.2).
3. Tighten `parse_diag_loc` in `lsp.cc` to check all-digits before `:` (§2.4).
4. Upstream the `ifa/` fixes with a `pyc` regression run (§2.5).
5. Document (or support) private helper macros called by exported macros (§2.3).
