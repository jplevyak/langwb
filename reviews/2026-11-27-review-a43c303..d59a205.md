Top findings:

1. **Declaring `type T = ...` after an `import` clobbers any already-imported
   module's `AdtDef` of the same name and erases its constructors (§2.1).**
   `import_module_file` qualifies incoming name collisions (`stem::Opt`), but
   `decl_type` / `PrimRegistry::register_adt` still keys replacement on
   `existing.name == adt.name` without checking `origin_module`. `type Opt = ...;
   import "b.ml"; ...` succeeds, whereas `import "b.ml"; type Opt = ...; ...`
   erases `a.ml`'s variants from `variant_map_` and fails inside `a.ml` with
   `unbound identifier 'Som'` — even when `Opt` was private to `a.ml` / `b.ml`
   and never exported to the importer.
2. **`#lang` macro re-scoping (`LangMacroReg`) misses root `Workbench::load_lang`
   (`--repl` and C++ embedders) and `.lang` `syntax_ext` blocks, and procedural
   macros inside `syntax_ext` crash with `SIGBUS` (§2.2).** Loading `#lang mlite`
   in `--repl` and running
   `import "examples/mlite/std/option.mlite"; case Some(42) of Some(v) => v | None => 0 end`
   fails on the same line with `constructor 'Some' of type 'Option' is not
   imported here` because `Workbench`'s clone constructor drops
   `lang_macro_regs_` and `eval_impl` only re-scopes `session_lang`. Macros in
   a `.lang`'s `syntax_ext` also lack `mod_scope` (and any procedural `macro` /
   `form_macro` in `syntax_ext` captures stack-allocated `ext_wb` by `this` and
   crashes on invocation).
3. **LSP `DocIndex::ctors` is not filtered by constructor visibility, causing
   Go-to-Definition on local binders to jump to private or unimported module
   types (§2.3).** Contrary to §7's assumption that a document naming an
   invisible constructor fails evaluation and has no index, a valid document
   that binds its own variable or parameter (`val Some = 42`, `fun test(None)`,
   `def Hidden = ...`) evaluates cleanly (`res.ok == true`), has no `idx.defs`
   entry on the binder token, and falls through to `idx.ctors` — jumping to an
   unimported transitive module (`option.mlite`) or a directly imported module's
   private `type`.

## 2. Concrete findings

### 2.1 [High] Declaring `type T = ...` after `import` overwrites an already-imported module's `AdtDef` of the same name and erases its constructors

`27d94ec` and `17e4e21` taught `Workbench::import_module_file`
(`src/workbench/workbench.cc:2931-2980`) to compare `(unqualified_name(),
origin_module)` against `prims_.adts()` and qualify an incoming colliding type to
`stem::Name` (`adt.declared_name = raw_adt.unqualified_name()`, `adt.name =
qual`).

However, `decl_type` (`src/workbench/workbench.cc:1053-1105`) registers local
types directly via `prims_.register_adt(std::move(adt))`, and
`PrimRegistry::register_adt` (`src/ifa_bridge/prim_registry.h:81-93`) matches
existing types by `existing.name == adt.name` alone, ignoring `origin_module`:

```cpp
void register_adt(AdtDef adt) {
  for (auto &existing : adts_) {
    if (existing.name == adt.name) {
      for (const auto &old_v : existing.variants) {
        variant_map_.erase(old_v.name);
      }
      for (const auto &v : adt.variants) {
        variant_map_[v.name] = v;
      }
      existing = std::move(adt);
      return;
    }
  }
```

As a result, `type` + `import` is order-dependent, and even a **completely
private** transitive `type` in an imported module breaks when a downstream
module or entry later declares a `type` with the same name:

1. **Private transitive type clobbered by importer (`import` before `type`):**
   `a.ml` defines `type Opt = Non | Som(v)` without exporting `Opt`, `b.ml`
   imports `a.ml`, and the entry imports `b.ml` and defines its own `type Opt =
   Foo | Bar(x)`:

   ```sh
   tmpdir=$(mktemp -d)
   printf 'type Opt = Non | Som(v);\ndef mk = fn(x) => Som(x);\ndef get = fn(o) => match o { Som(v) => v, Non => 0 };\nexport mk, get;\n' > "$tmpdir/a.ml"
   printf 'import "a.ml";\ndef wrap = fn(x) => get(mk(x));\nexport wrap;\n' > "$tmpdir/b.ml"

   # `type` before `import`: succeeds (a.ml's Opt is qualified to a::Opt)
   ./langwb -e "type Opt = Foo | Bar(x); import \"$tmpdir/b.ml\"; match Bar(wrap(10)) { Bar(v) => v, Foo => 0 }"
   # => 10

   # `import` before `type`: erases Non/Som and fails inside a.ml!
   ./langwb -e "import \"$tmpdir/b.ml\"; type Opt = Foo | Bar(x); match Bar(wrap(10)) { Bar(v) => v, Foo => 0 }"
   # .../a.ml:2:18: error: unbound identifier 'Som'

   rm -rf "$tmpdir"
   ```

2. **Same failure inside an imported module (`m2.ml` imports `a.ml` then
   declares `type Opt = Foo | Bar(x);`)** and when `a.ml` *does* export `Opt`
   (`type Opt = Foo | Bar(x); import "a.ml"; { a: Bar(1), b: Som(2) }` evaluates
   to `{ a: Bar(1), b: Som(2) }`, while swapping the first two forms fails with
   `a.ml:2:18: error: unbound identifier 'Som'`).

**Suggested fix:** Only treat `existing.name == adt.name` in
`PrimRegistry::register_adt` as an in-place replacement when
`existing.origin_module == adt.origin_module`. When a newly declared `type Name`
(`adt.origin_module.empty()`) collides with an already-imported `existing`
(`!existing.origin_module.empty()` and `existing.name == adt.name`), qualify the
existing imported `AdtDef` in `prims_` to `stem::Name` (`existing.declared_name
= existing.name`, `existing.name = qual`, updating `v.type_name = qual` in both
`adts_` and `variant_map_`) before appending `adt`, making both declaration
orders symmetric.

### 2.2 [High] `#lang` macro re-scoping (`LangMacroReg`) misses root `Workbench::load_lang` (`--repl`, C++ API) and `.lang` `syntax_ext` blocks; procedural macros in `syntax_ext` crash with `SIGBUS`

In `17e4e21`, `Workbench::eval_impl` (`src/workbench/workbench.cc:3346-3354`)
re-registers `session_lang->lang_macro_regs_` wrapped with the entry's
`mod_scope` so macro-synthesized AST nodes (`__wb_is_variant` in MLite's `case`)
carry `mod_scope` and pass `v->visible_to(node->scopes)` for imported
constructors:

```cpp
if (session_lang) {
  for (const LangMacroReg &r : session_lang->lang_macro_regs_) {
    session.register_scoped_macro(r.is_stage1 ? session.stage1_ : session.stage0_, r.is_form,
                                  r.name, r.fn);
  }
}
```

Two macro paths miss this `mod_scope` wrapping, and testing the second exposed a
dangling-`this` crash in `decl_syntax_ext`:

1. **Root `Workbench::load_lang` (`--repl` and C++ embedders):** When `#lang
   mlite` is loaded onto a root `Workbench` (`src/cli/main.cc:365`),
   `lang_macro_regs_` is recorded on `wb` with `decl_scope_ == 0`. On subsequent
   REPL lines (or `wb.eval_*` calls), `has_lang` is `false` (`session_lang ==
   nullptr`), and `Workbench::Workbench(const Workbench &parent, bool)`
   (`src/workbench/workbench.cc:187-204`) does not copy `lang_macro_regs_`.
   `session` therefore never wraps MLite's `case` macro with `mod_scope`, and
   every pattern match on an imported constructor in `--repl` fails:

   ```sh
   printf '#lang mlite\nimport "examples/mlite/std/option.mlite"; case Some(42) of Some(v) => v | None => 0 end\n:q\n' \
     | ./langwb --repl
   # <input>:1:59: error: constructor 'Some' of type 'Option' is not imported here
   #   (module 'option.mlite' exports it; import it or re-export 'Option' from the module you import)
   ```

2. **Macros inside a `.lang` file's `syntax_ext` block:** In `decl_syntax_ext`
   (`src/workbench/workbench.cc:982-1011`), `Workbench ext_wb(*this, true)` has
   `loading_lang_depth_ == 0` and `decl_scope_ == 0`, and `using syntax`
   (`src/workbench/workbench.cc:229`) merges `it->second.stage0_delta` without
   wrapping `.lang`-defined extension macros with the active module's
   `decl_scope_`:

   ```sh
   tmpdir=$(mktemp -d)
   cat > "$tmpdir/extlang.lang" <<'EOF'
   syntax_ext is_opt {
     grammar expr += check_som_e core(passthrough);
     grammar check_som_e : 'issom' expr $right 0;
     syntax_rule form check_som_e(_, $x:expr) => if __wb_is_variant($x, "Som", 1) then 1 else 0;
   };
   EOF
   printf 'type Opt = Non | Som(v);\ndef mk = fn(x) => Som(x);\nexport Opt, mk;\n' > "$tmpdir/a.ml"
   ./langwb -e "#lang $tmpdir/extlang.lang
   import \"$tmpdir/a.ml\";
   using syntax is_opt in { issom mk(5) }"
   # <input>:3:25: error: constructor 'Som' of type 'Opt' is not imported here ...
   rm -rf "$tmpdir"
   ```

3. **Stack use-after-return (`SIGBUS`) on procedural macros inside `syntax_ext`:**
   In `decl_syntax_ext` (`src/workbench/workbench.cc:986`), `ext_wb` is
   stack-allocated and destroyed at line 1011, whereas
   `ext_wb.register_guest_macro_stx` (`src/workbench/workbench.cc:2437`) captures
   `[this]` (`&ext_wb`). Any procedural `macro` or `form_macro` inside
   `syntax_ext` crashes on expansion:

   ```sh
   ./langwb -e 'syntax_ext dbl { macro twice_x => let a = stx_arg(stx_call(), 0) in stx_splice(stx_parse("expr", "__x__ + __x__"), "__x__", a); };
   using syntax dbl in { twice_x(21) }'
   # Bus error: 10 (exit code 138)
   ```

**Suggested fix:**
- Copy `lang_macro_regs_(parent.lang_macro_regs_)` in
  `Workbench::Workbench(const Workbench &parent, bool)`, and in `eval_impl`
  re-register `const auto &regs = session_lang ? session_lang->lang_macro_regs_
  : lang_macro_regs_;` when `!regs.empty()`.
- Allocate `ext_wb` via `std::shared_ptr<Workbench>` stored on `SyntaxExtDelta`
  (matching `ImportedModule::owner` at `src/workbench/workbench.h:237`), record
  unwrapped `LangMacroReg`s on `SyntaxExtDelta` when defined with
  `decl_scope_ == 0`, and wrap them with `child.decl_scope_` inside
  `init_using_syntax_hook` when `child.decl_scope_ != 0`.

### 2.3 [Medium] LSP `DocIndex::ctors` is not filtered by constructor visibility, jumping to private or unimported module declarations on local binders

`docs/STEP12_5_MODULE_SEMANTICS.md` §3.2 originally planned to filter
`DocIndex::ctors` to constructors visible in the entry module. §7 (lines
567–571) left `DocIndex::ctors` (`src/workbench/lsp.cc:489-494`) unfiltered on
the assumption:

> *"The text fallback (`DocIndex::ctors`, used for pattern words) is not
> filtered: a document that names an invisible constructor does not evaluate, so
> it has no index."*

That assumption fails whenever a valid document (`res.ok == true`, zero
diagnostics) defines its **own** variable, function, or parameter with the same
identifier as:
- an unimported transitive constructor (`Some` / `None` from `option.mlite` when
  importing `result.mlite`), or
- a **private, unexported** constructor of a directly imported module (`Hidden`
  in `priv_mod.ml`).

Because `index_defs` (`src/workbench/lsp.cc:451-477`) only emits `DefEntry`
records on *references* (`bid != 0` or `CoreFormKind::Ident` constructor uses),
binder tokens (`val Some = 42`, `fun test(None) = ...`, `def Hidden = ...`,
`fn(Hidden) => ...`) have no entry in `idx.defs`. `definition_result`
(`src/workbench/lsp.cc:554-565`) therefore falls through to
`constructor_word_at` → `idx.ctors` and jumps into the hidden or unimported
module:

```sh
python3 - <<'PY'
import json, os, shutil, subprocess, tempfile

def frame(o):
    s = json.dumps(o)
    return f"Content-Length: {len(s)}\r\n\r\n{s}".encode()

def read_msg(fd):
    hdr = b""
    while b"\r\n\r\n" not in hdr:
        hdr += os.read(fd, 1)
    cl = int(hdr.decode().split("Content-Length:")[1].split("\r\n")[0].strip())
    body = b""
    while len(body) < cl:
        body += os.read(fd, cl - len(body))
    return json.loads(body.decode())

tmp = tempfile.mkdtemp()
try:
    doc_path = f"{tmp}/entry.mlite"
    doc = (
        "#lang mlite\n"
        f'import "{os.path.abspath("examples/mlite/std/result.mlite")}";\n'
        "val Some = 42;\n"
        "fun test(None) = Some + None;\n"
        "test(1)\n"
    )
    open(doc_path, "w").write(doc)
    uri = f"file://{doc_path}"
    p = subprocess.Popen(["./langwb", "--lsp"], stdin=subprocess.PIPE, stdout=subprocess.PIPE)
    p.stdin.write(frame({"jsonrpc":"2.0","id":1,"method":"initialize","params":{}}))
    p.stdin.write(frame({"jsonrpc":"2.0","method":"textDocument/didOpen","params":{
        "textDocument":{"uri":uri,"languageId":"mlite","version":1,"text":doc}
    }}))
    p.stdin.write(frame({"jsonrpc":"2.0","id":2,"method":"textDocument/definition","params":{
        "textDocument":{"uri":uri},"position":{"line":2,"character":4}  # `val Some = 42`
    }}))
    p.stdin.flush()
    read_msg(p.stdout.fileno())  # initialize
    read_msg(p.stdout.fileno())  # publishDiagnostics ([])
    print(read_msg(p.stdout.fileno()))
    # -> jumps to examples/mlite/std/option.mlite:3:21 even though option.mlite is not imported!
    p.stdin.write(frame({"jsonrpc":"2.0","id":3,"method":"shutdown","params":{}}))
    p.stdin.write(frame({"jsonrpc":"2.0","method":"exit","params":{}}))
    p.stdin.flush()
    p.wait(timeout=5)
finally:
    shutil.rmtree(tmp, ignore_errors=True)
PY
```

**Suggested fix:** Record the entry module's `ScopeId` on `InspectResult`
(`syntax::ScopeId entry_scope = 0;` set in `eval_impl` / `eval_single_expr`) and
filter `idx.ctors` in `build_doc_index` (`src/workbench/lsp.cc:489-494`) to
variants visible in `entry_scope` (`v.visible_in.empty()` or `entry_scope` in
`v.visible_in`), then update the §7 M2b note in
`docs/STEP12_5_MODULE_SEMANTICS.md:567-571`. Emitting self-definitions on binder
tokens in `index_defs` would also prevent binder clicks from falling through to
any text-based constructor lookup.

## 3. Minor / polish items

1. **Cross-module variant collision diagnostics omit the defining module and
   cascade into `invalid declaration near '...'`
   (`src/workbench/workbench.cc:1078-1082, 3131-3136, 3394-3399`):** Same-named
   private constructors across modules are explicitly deferred in
   `docs/STEP12_5_MODULE_SEMANTICS.md` §5 and `docs/ROADMAP.md`, so rejecting a
   duplicate constructor name is expected today. However, when `b.ml` privately
   imports `a.ml` (`type Opt = Non | Som(v)`) and an importer of `b.ml` writes
   `type MyOpt = Som(x);`, `decl_type` reports:
   - `<input>:1:...: error: variant 'Som' is already defined by type 'Opt'`
     (without naming `a.ml`, even though `Opt` was never imported into `<input>`),
     followed immediately by a redundant second error:
   - `<input>:1:...: error: invalid declaration near 'type MyOpt = Som(x); ...'`
     (also emitted in `import_module_file` at line 3134 whenever
     `parse_and_apply_decl_prefix` fails after `apply_decl_cst` has already
     reported a specific diagnostic).
   Naming `origin_module` when non-empty and suppressing the fallback
   `invalid declaration near` message when `parse_and_apply_decl_prefix` already
   emitted an error would make both diagnostics cleaner.
2. **Transitive `private_variant_note` re-export hint over 2+ non-exporting hops
   (`src/ifa_bridge/bridge.cc:84-86`):** When `a.ml` exports `Opt`, `b.ml`
   imports `a.ml` without re-exporting `Opt`, `c.ml` imports `b.ml`, and the
   entry imports `c.ml` and names `Som(1)`, `private_variant_note` suggests
   `(module 'a.ml' exports it; import it or re-export 'Opt' from the module you
   import)`. Adding `export Opt;` to `c.ml` alone will warn `'Opt' exported from
   'c.ml' is not defined` unless `b.ml` also re-exports `Opt` (importing `a.ml`
   directly works as suggested).
